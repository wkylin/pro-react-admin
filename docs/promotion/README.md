# 推广执行包

面向准备搭建内部管理工具的 React 团队。第一轮让开发者先试用成员、审批与审计界面，再判断是否值得拉取源码。主张统一为：**从一套可运行的管理流程，开始团队自己的 React 后台。**

本目录是待审阅的内容包，更新于 **2026-11-09**。文案尚未发布，未联系外部用户；制作素材不等于线上版本已更新。各渠道可复制的正文见[推广文案草稿](./launch-copy.md)。

## 统一入口与事实边界

| 用途           | 地址                                                                    | 使用方式                               |
| -------------- | ----------------------------------------------------------------------- | -------------------------------------- |
| 主体验入口     | [公开访问管理预览](https://pro-react-admin.vercel.app/#/preview/access) | 所有渠道共用；无需登录，只读、虚构数据 |
| 源码与本地运行 | [GitHub 仓库](https://github.com/wkylin/pro-react-admin)                | 体验后的第二步                         |
| 组件细节       | [Storybook](https://wkylin.github.io/pro-react-admin/storybook/)        | 供需要检查组件的开发者继续查看         |

公开预览展示成员、审批和审计，不提供写操作。完整后台的通知编辑、查询和页面模板需要登录；本轮录屏中的这些操作使用本地演示环境。仪表盘继续使用演示数据，通知与业务页面模板的记录也不代表生产业务 API。

源码提供 Enterprise 项目预设及服务端资源能力；上线仍需团队完成自己的身份、数据、权限和部署配置。推广时不使用“开箱即生产可用”、认证背书、节省时间百分比或客户数量等未经验证的表述。

## 发布前验收

以下项目由发布者完成并记录实际结果。未勾选的项目不能在对外文案中写成已上线。

- [ ] 无痕窗口打开主体验入口，无需账号即可切换概览、成员、审批和审计。
- [ ] 成员搜索可用；浏览器刷新后仍能打开当前预览地址；页面保留只读和虚构数据说明。
- [ ] 手机宽度检查预览，主要信息、表格和体验入口可访问。
- [ ] GitHub README 中英文首屏、预览链接、截图和本地启动命令与当前提交一致。
- [ ] Storybook 地址可打开；若不可用，从本轮发布文案移除该次要链接。
- [ ] 录屏、截图来自同一版本，未出现本地账号凭据、私有信息或开发者面板。
- [ ] 录屏中通知编辑与主题切换已在目标版本验收；本地演示与公开只读预览的区别清晰。
- [ ] 发布者审阅草稿并确认渠道、时间和最终正文；本包本身不执行对外发布。

建议记录：验收日期、提交 SHA、预览地址、桌面/手机浏览器、未解决问题。若公开站点仍是旧版本，应先保留对应截图与描述，待部署验收后再替换。

## 45 秒演示分镜

视频已在本地演示环境录制。成片由三段实际操作、手机主题截图对照和片尾组成，为阅读调整了播放节奏，无旁白。界面与字幕均保留演示数据说明；剪辑不改变操作结果。以下分镜对应当前 45 秒成片。

| 时间     | 画面与操作                                                         | 屏幕字幕 / 旁白                                                     | 验收重点                                               |
| -------- | ------------------------------------------------------------------ | ------------------------------------------------------------------- | ------------------------------------------------------ |
| 0–8 秒   | 打开后台工作区，停留在概览，展示主导航与仪表盘                     | “从可运行的管理流程，开始你的 React 后台。” / “本地演示 · 示例数据” | 让人看清布局与主任务，避免快速扫过大量工程菜单         |
| 8–20 秒  | 切到公开访问管理预览；搜索一名成员，再切换审批、审计标签           | “免登录查看成员、审批与审计。公开预览为只读。”                      | 不演示审批通过或成员变更，保持事实边界                 |
| 20–32 秒 | 切回已登录的本地后台；打开通知、编辑标题并保存，再筛选定位该条记录 | “通知编辑、校验与筛选，连成一次完整操作。” / “本地演示 · 会话数据”  | 保存结果与实际操作一致；明确记录只属于本地演示会话     |
| 32–40 秒 | 对照手机宽度下通知列表的浅色与深色真实截图                         | “桌面与手机，使用同一套页面规则。”                                  | 操作入口可见，两种主题的信息可读                       |
| 40–45 秒 | 停在公开预览入口与仓库地址                                         | “先试用，再看源码。”                                                | 主体验地址与仓库地址可读；不加入请求点赞或 Star 的字幕 |

录制准备：固定演示语言和窗口尺寸；先登录本地后台；准备一条可编辑的虚构通知；收起调试工具；用字幕明确本地操作。可保留必要剪辑，但不把演示记录称为真实业务数据。

## 来源与体验记录

本包没有新增统计 SDK。没有可核实的计数时填“未采集”，不要根据浏览量估算体验人数。第一轮可先使用发布后台的可见计数和用户自愿提供的反馈。

| 日期 | 渠道 / 发布 URL | 内容版本 / 提交 | 可核实来源访问数及口径 | 已确认体验人数 | 已确认本地运行人数 | 有效反馈数 | 下一步 |
| ---- | --------------- | --------------- | ---------------------- | -------------- | ------------------ | ---------- | ------ |
| 待填 | 待填            | 待填            | 未采集                 | 未采集         | 未采集             | 未采集     | 待填   |

- **来源访问**：明确写明是渠道帖子阅读、仓库访客还是站点访问；不同口径不相加。去重能力未知时不称“独立访客”。
- **已确认体验**：用户明确反馈已打开预览并完成成员搜索或切换审计；仅点击、点赞或 Star 不计入。
- **已确认本地运行**：用户明确反馈成功启动，并注明所用提交、环境与命令；未得到反馈不推断成功。
- **有效反馈**：能对应到具体任务、页面、复现步骤或采用障碍；同一问题重复报告同时记录人数与问题条数，避免混算。

如后续使用来源参数，先验证现有统计确实采集并能保留 hash 路由；参数应放在 `#` 前。未接入前继续使用统一主链接和反馈中的来源字段，不以加了参数代表已经有转化统计。

### 单条反馈模板

```text
日期 / 来源：
使用场景：希望用它搭建什么管理工具？
版本 / 地址：
设备 / 浏览器 / 本地环境：
任务：预览成员与审计 / 本地启动 / 修改列表字段
结果：完成 / 卡住 / 未尝试
复现步骤与实际结果：
期待结果：
是否影响继续试用：是 / 否
处理决定 / issue：
```

记录技术事实即可，不要求反馈者提供真实客户、业务数据或账号凭据。公开回复先确认问题和修复状态，不承诺尚未排期的功能。
