# 个人资料：账号、展示资料与偏好

默认展示应用的个人资料页位于 `/#/profile`，也可以从头像菜单的个人中心进入。页面展示当前登录账号，支持编辑保存在当前浏览器的展示资料，并复用现有主题、语言和紧凑布局设置。

## 体验流程

在仓库根目录运行 `pnpm start`，按终端打印的地址登录，再打开侧栏“个人资料”或 `/#/profile`。启动环境和演示账号见[快速上手](./GETTING_STARTED.md)。

1. 在账号区域查看当前账号、邮箱、用户 ID 和角色。未提供的信息显示为空态，不使用原作者的履历、工作年限或虚构活动统计。
2. 点击“编辑资料”，填写显示姓名、职位、部门、所在地和简介。显示姓名为 1–60 字，其余字段可留空；职位、部门和所在地最多 80 字，简介最多 280 字。字段两端空白会被清理。
3. 保存后检查本页展示内容，再刷新页面；同一账号的本地展示资料会恢复。账号身份、登录邮箱、角色和头像菜单中的登录信息不会被展示资料覆盖。
4. 修改资料后取消，选择“继续编辑”可保留草稿；选择“放弃修改”关闭草稿，已保存内容保持原样。
5. 在偏好区域选择浅色、深色或跟随系统主题，切换中文/English，或启用紧凑布局。设置立即生效，刷新后沿用原有设置存储规则。

快捷入口仅展示当前账号可访问且当前项目已经注册的页面。验证器入口需要真实 Enterprise 会话及对应页面权限；本页不生成“已开启两步验证”等未经查询的安全状态。

## 三类数据的边界

| 数据       | 来源与保存范围                                               | 可在本页修改的内容                     |
| ---------- | ------------------------------------------------------------ | -------------------------------------- |
| 账号身份   | `useAuth` 与当前权限服务；Enterprise 身份来自既有会话        | 只读；不修改登录邮箱、角色、权限或凭据 |
| 展示资料   | 当前浏览器的带版本本地记录，按项目、登录来源、租户和账号隔离 | 显示姓名、职位、部门、所在地、简介     |
| 外观与语言 | 复用主题 Context 与 i18n；主题按项目保存，语言沿用浏览器设置 | 主题、语言、紧凑布局，立即生效         |

展示资料仅改变本页的展示，不会调用个人资料 API、管理员用户资源 API 或 GitHub 资料更新 API，也不代表跨设备同步。页面不把 token、密码、登录邮箱或权限写入展示资料记录。

同一浏览器切换账号时会按身份重新读取展示资料，避免前一账号内容留在后一账号页面。浏览器禁止读取本地存储时，页面使用账号默认值并提示；记录版本、JSON 或字段无效时回退默认资料。写入失败会保留编辑草稿，不显示保存成功。

## 页面与源码

- [页面](../../src/pages/profile/index.tsx)复用 [BusinessPage](../../src/shared/ui/BusinessPage/index.tsx)，组合账号、展示资料、偏好和快捷入口。
- [编辑弹窗](../../src/pages/profile/ProfileEditor.tsx)负责字段标签、校验反馈、保存及草稿取消确认。
- [展示资料模型](../../src/pages/profile/model.ts)负责默认值、字段校验、版本记录、本地存储读写和身份存储键；[模型测试](../../src/pages/profile/model.test.ts)覆盖损坏/不可用存储、校验与隔离。
- [认证 Hook](../../src/platform/auth/hooks/useAuth.ts)和[权限 Hook](../../src/platform/auth/hooks/usePermission.ts)提供当前账号及角色；[会话通知](../../src/platform/auth/model/session.ts)驱动认证状态刷新，页面按项目和账号键重新挂载展示资料区域。
- [主题 Context](../../src/theme/hooks.tsx)与 i18n 继续承担偏好设置；本页不另建主题或语言状态。

`/profile` 保持原有默认展示应用注册和 `profile:read` 访问策略；本轮不自动扩展 Enterprise 路由。若要接入真实个人资料，应另行实现按当前会话授权的服务端接口、校验、存储和刷新机制，不能直接复用管理员用户编辑接口来冒充自助资料更新。身份与服务端资源边界见[用户角色权限](../architecture/USER_ROLE_PERMISSION.md)和[企业资源指南](../operations/ENTERPRISE.md)。

## 验证命令

在仓库根目录运行模型、类型、文案与工程检查：

```bash
pnpm exec jest --config tests/unit/config.cjs --runInBand src/pages/profile/model.test.ts
pnpm run typecheck
pnpm run test:e2e:typecheck
pnpm run check:i18n
pnpm run check:route-contract
pnpm run check:docs
```

默认应用先构建，再执行 [Profile 浏览器用例](../../tests/e2e/profile.spec.ts)：

```bash
pnpm run build:webpack
pnpm exec playwright test --config tests/e2e/config/app.config.ts tests/e2e/profile.spec.ts
```

浏览器用例覆盖当前身份、本地保存与刷新恢复、草稿取消确认、同标签页账号切换隔离，以及主题、语言、密度和 390px 深色布局。实际执行结果以本轮验收记录为准；格式与文档检查不能替代行为验收，开发服务结果不能替代生产构建和部署验证。
