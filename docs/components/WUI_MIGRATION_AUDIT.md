# WUI React 6.1.0 组件迁移审核

本清单冻结于 2026-10-28，源码基线为 `5307852d77fa3002fd1c5b8fbb962af76429b57f`。依据[批准的迁移设计](../superpowers/specs/2026-10-28-wui-react-component-migration-design.md)，审核全部 **143** 个直接目录：139 个 stateless、4 个 stateful。

结论：**2 migrate**、**131 adapt then migrate**、**10 keep in app**。前两类合计 **133** 个目录均属于同一次 6.1.0 发布范围；“改造后迁入”不是延期或已通过发布质量检查的声明。

## 证据与检查

机器清单是 [config/wui-migration-roster.json](../../config/wui-migration-roster.json)。每个条目记录直接目录、当前依赖、逐文件 SHA-256、import 的文件及行号、具体接口改造、目标分组和判定理由。依赖从 TypeScript AST 提取，包括嵌套实现的静态 import、re-export、动态 import 和 require；忽略注释、故事、测试与手写声明中的 import。type-only import 在证据中单独标记；表中 packages 是当前引用的包，并非最终 runtime/peer 声明。

只把直接目录计为条目。OrgChart/org-chart、MdxEditor/components、FixMusicPlayer/hooks、InteractiveBook 引擎等随父目录移动，不另增组件计数。证据文件包含运行实现、样式和本地资源；测试、故事与声明不参与源码快照。当前 app/shared/hooks/theme 等传递依赖必须在迁移时替换或抽离，不能因本表只列直接 import 而保留应用耦合。

运行 `node scripts/validate-wui-migration-roster.mjs` 检查冻结名单、字段与审核表一致性；迁移前加 `--check-source` 会逐项比对实际目录、源码摘要及 import 位置。迁移后不再把旧路径是否存在当作完成标准，后续发布检查应按 destination 和 decision 验证所有迁入项。修改机器清单后用 `--write-doc` 同步此表。

## 所有迁入项的共同要求

- 发布严格的 TypeScript props、事件、ref 和数据类型；不得用隐式 any 或仅 PropTypes 代替公共契约。
- 样式独立：将组件 Less/CSS、Tailwind 工具类及所需 keyframes 编译或重写为包内样式；为应用主题变量提供包内默认值，不要求消费者引入应用 Tailwind/主题。
- 清除所有应用服务、私有资产、旧组件路径、固定演示数据及项目文案。真正通用的浏览器逻辑可抽为包内 helper；业务/i18n/路由接线留在应用适配层。
- 渲染及模块加载在服务端安全；检查 observer、timer、RAF、事件、媒体、异步任务的卸载清理，交互具备可访问名称和键盘行为。
- 迁入理由不是发布质量认证；逐组运行严格类型、构建、独立 ESM/CJS/样式消费与相关行为检查，维持既有 250 文件和体积预算。

目标分组是命名导出的 `@w.ui/wui-react/<group>`；目标源码目录写在机器清单中。现有 12 个独立子路径保持兼容。依赖重的分组必须采用可选 peer/分组入口，不允许轻量根入口导入这些分组；最终依赖版本在 library-contract、manifest 和文档中一致声明。移除的示例数据仍可留在应用/Storybook。
