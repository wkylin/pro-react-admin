# CRM Demo Implementation Plan

> **For agentic workers:** Use the approved scope below to deliver and review the CRM workflow in this workspace. Preserve prior uncommitted work; do not commit, publish or deploy.

**Goal:** Make fictional customers, follow-ups and opportunities form a working CRM demo journey.

**Architecture:** An independent CRM module owns one in-memory Zustand store per Provider instance. Three routes reuse BusinessPage and BusinessToolbar; only the customer workspace appears in the existing page-pattern menu. Both showcase applications register the module.

**Tech Stack:** React 19, TypeScript, Zustand, Ant Design, React Router, i18next, Jest and Playwright.

**Spec:** `docs/superpowers/specs/2026-11-09-crm-demo-design.md`

## Global constraints

- Demo data only; no API, localStorage, dependency or generated-preset changes.
- Keep existing top-level menu and use `home:read` for the three demo routes.
- Persist currency as integer cents; validate writes before changing state.
- Use the existing theme tokens, shared business layout and bilingual copy.
- Preserve all earlier work and leave Git history untouched.

## Review focus

- Invalid relationships and malformed values leave the whole state unchanged.
- Won/lost terminal states cannot advance or double-count pipeline totals.
- Customer and opportunity lists remain consistent after a detail mutation.
- Cancelled forms do not silently discard data; unknown details have a usable way back.
- Module instances remain isolated and narrow layouts keep controls reachable.

## Task 1 — domain and session Provider

Files: `src/features/crm/model/{types.ts,crmStore.ts,crmStore.test.ts,CrmProvider.tsx}`.

Public interface: `createCrmStore({ now?: () => Date }?)`, `CrmProvider`, `useCrmStore<T>(selector)`.
State: `customers`, `followUps`, `opportunities`; actions `createCustomer(draft)`, `updateCustomer(id,draft)`, `addFollowUp(draft)`, `createOpportunity(draft)`, `advanceOpportunity(id,expectedStage)`, `loseOpportunity(id,reason)`. Advancement requires the record's current stage to equal the stage shown when the action was rendered, so replaying a stale action cannot advance again.

Types: `CustomerDraft { company, contact, email, owner }`; `FollowUpDraft { customerId, kind, content, nextFollowUpOn? }`; `OpportunityDraft { customerId, title, amount, expectedCloseOn }`. Owners `lin|chen|zhou`, customer status `lead|customer`, kinds `call|email|meeting|note`, stages `discovery|proposal|negotiation|won|lost`. Records include stable `id` and `createdAt`; customers/opportunities include `updatedAt`; opportunities store `amountCents` and optional `lostReason`.

Export selectors `getPipelineSummary(opportunities)` returning `{ openCount, openAmountCents, wonAmountCents }` and `CrmValidationError` with localized error code `customerMissing|opportunityMissing|company|contact|email|owner|kind|content|date|title|amount|stage|lostReason`.
