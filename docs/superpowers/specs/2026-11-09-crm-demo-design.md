# CRM 演示流程

## 授权与目标

用户要求落实下一阶段 CRM 演示流程，继续保留演示数据。本轮直接完成客户、跟进与商机的可操作闭环，供准备搭建内部管理工具的 React 团队参考。

沿用已批准的逐步迭代方向。本轮实现选择由开发者根据现有代码作出，不增加外部服务、依赖或真实业务 API。

## 实现选择

比较了扩展通用申请模板、独立 CRM 模块及新增 CRM 顶层导航三种方式。采用独立 `crmModule`，复用共享页面布局，在既有业务模板下只加一个入口：领域关系可以独立验证，也不会增加顶层菜单密度。默认展示应用与现有 Enterprise 展示入口注册模块；生成 Enterprise 项目预设保持现有模块集合。

- `/patterns/crm`：客户列表，搜索、状态筛选、分页、新建与编辑客户。
- `/patterns/crm/customers/:id`：客户详情、跟进时间线、新建跟进与关联商机。
- `/patterns/crm/opportunities`：商机表格、阶段筛选与推进；只从 CRM 页面内进入。
- 隐藏详情路由回到 CRM 菜单入口；未知客户提供返回入口。

## 业务规则

- 客户：公司、联系人、电子邮箱、负责人、潜在/已成交状态。公司 2–100 字，联系人 1–80 字，邮箱合法且不超过 120 字。负责人使用固定演示团队 `lin`、`chen`、`zhou`。
- 新建客户默认为潜在客户；编辑基本信息不允许手动改状态。首个商机赢单后自动成为已成交客户。
- 跟进必须关联现有客户；方式为 `call`、`email`、`meeting`、`note`，内容 4–1000 字，可附合法 `YYYY-MM-DD` 的下次跟进日期。新记录出现在详情时间线，并更新客户下次跟进日期。
- 商机必须关联现有客户；标题 2–100 字，金额输入采用人民币元，领域模型保存整数分，正数、最多两位小数、最高 100,000,000 元；预计成交日期必须为合法 `YYYY-MM-DD`。
- 阶段依次为 `discovery → proposal → negotiation → won`。任一未结束阶段可标记 `lost`，丢单原因 4–500 字。终态不能继续推进或丢单；重复提交不能产生额外状态变化。
- 创建商机始于 discovery；不支持跨阶段跳转和直接编辑关联客户。各列表、详情与汇总读取同一状态，搜索和筛选不改变业务数据。
- 汇总区显示全部商机的未结束数量/金额、已赢单金额；关闭后的商机不计入未结束金额。客户详情只汇总自己的商机。
- 字段两端空白由领域层清理；非法输入、未知关联与非法阶段更新不修改现有数据。

## 数据与状态边界

模块 Provider 按实例创建 Zustand 内存 store，切页共享、刷新或卸载重置；不同实例隔离。不读写 localStorage，不请求 Enterprise API。演示记录采用虚构公司和联系人，种子时间由注入时钟生成。

模块路由采用与现有业务页面模板一致的 `home:read`，两份 route-policy 保持一致。此权限只控制演示入口，不宣称生产 CRM 写权限；服务端权限和真实数据集成留待独立阶段。

## 界面约定

扩展现有界面系统，使用 `BusinessPage`、`BusinessToolbar`、Ant Design 控件和已有 Geist 字体。页面间距 24px，手机 16px，局部间距 8/12/16/24px；色彩使用 `--wui-text-*`、`--wui-color-*`、`--wui-border-*` 与背景语义变量，不建立独立主题。

客户列表的唯一主操作是新建客户。详情主操作是记录跟进，关联商机区域提供创建商机；商机工作区展示阶段和下一步操作。表单具备明确标签、内联校验、保存结果及取消入口；取消已填写表单需要丢弃确认。双语文案说明虚构数据及刷新重置规则，不将工程实现细节混入操作步骤。

桌面表格放在可滚动的区域内；390px 宽度时工具条换行、详情单列、页面本身无横向溢出。状态同时显示文字，空结果提供清除筛选；未知记录可回到客户列表。明暗主题和键盘操作沿用共享控件。

## 验证

领域测试覆盖客户创建/编辑、跟进关联、金额与日期校验、阶段推进、丢单、赢单更新客户、原子失败、汇总与实例隔离。导航测试覆盖单入口和隐藏详情选中。浏览器验证完整创建/跟进/商机赢单、取消修改、筛选空态、刷新重置与手机/深色布局。执行类型、i18n、路由/项目契约、文档和受影响代码质量检查，并进行独立审阅。
