# 联系与反馈页完善

用户要求优化并完善 `#/contact`。现有页面具有 Web3Forms 发送链路，本轮保留发送能力，将其整理为工作台中的完整联系页。

## 选择

比较单纯换样式、只保留外链、保留表单并完善反馈流程三种方案。开发者选择第三种，复用 BusinessPage、主题变量和 Ant Design 表单，不新建邮件服务或引入依赖。

## 内容与布局

- 桌面两列：一侧是项目邮箱、GitHub Issues、项目指南及简短反馈说明；另一侧是有明确标签的留言表单。手机单列，主要发送操作可通过页面滚动到达。
- 真实联系方式依据 `package.json`：`wkylin.w@gmail.com`、`https://github.com/wkylin/pro-react-admin/issues`；指南链接至仓库 README，不虚构客服在线状态或回复时效。
- 使用已有 BusinessPage 和 Geist。页面/面板间距 24px、手机 16px；局部 8/12/16/24px；颜色来自现有背景、文本、边框和状态语义变量。
- 中英文文案、明暗主题、键盘可达、可见标签、长内容换行、空态和复制邮箱失败提示完整。

## 表单与边界

- 字段：姓名 1–80 字、合法回复邮箱（最多 254 字）、咨询类型 `question|bug|idea|collaboration`、主题 2–120 字、内容 10–4000 字。领域层清理空白并校验，保留可编辑输入。
- 真实租户或 GitHub 身份可预填已有姓名/邮箱；虚构测试账号不自动填入演示邮箱。跨账号/租户切换重新挂载表单，不带入上一身份草稿。
- 草稿仅留在当前页面会话，不写浏览器持久存储。切换工作台标签可保留草稿；清空已填写内容需确认；刷新前有未保存内容时使用浏览器原生离开提示。
- 点击发送后同步请求锁与禁用态阻止重复提交。发送期间不允许编辑/清空；组件卸载或身份切换中止旧请求。失败保留全部内容，供用户自主重试，不自动重试。
- Web3Forms endpoint 保持不变。必须同时满足 HTTP 成功、合法 JSON 对象和 `success === true` 才显示发送服务已接收；仅成功后恢复初始表单。成功不承诺邮件最终投递或人工回复。
- 明确处理未配置、拒绝、限流、网络、15 秒超时、异常响应和取消。超时/网络使用结果未确认的措辞，避免误称必定未送达。
- 页面说明留言通过 Web3Forms 转交。实现与验证阶段不发送真实邮件，不新增外部帖子、工单或消息。

## 配置

把现有公开表单 key 从组件迁到共享 `.env` 的 `REACT_APP_WEB3FORMS_ACCESS_KEY`，保留现有默认发送配置。加入共用浏览器变量白名单，支持部署者覆盖或设空停用；未配置时保留联系渠道、禁用发送并解释原因。此 key 是服务商允许用于浏览器的公开表单标识，不是服务器密钥。

`/contact` 的注册、权限与菜单位置不变；中文菜单名从“联系人”调整为“联系与反馈”，英文保留 Contact。
