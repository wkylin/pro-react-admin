# 推广基础第一阶段

## 目标

落实用户批准的渐进方案：先把中英文项目介绍、可复用视觉素材和公开体验入口做成一套可审阅交付，再进入业务案例、保存视图与全局操作迭代。

面向需要内部管理系统的 React 团队，主线为“可生成独立项目，内置租户、权限和审计示例的管理后台脚手架”。项目生成器、组件包和双构建已有实现，文案依据现有源码和验证入口，不承诺未经测量的性能、时间或采用量。

## 本阶段选择

保留现有工程网站和完整技术 README，重排首屏并增加精简英文版。主体验入口统一为现有 `/preview/access` 免登录只读预览；完整工作台继续使用原登录流程。采用真实本地演示截图和实际操作录屏，并明确素材来自本地版本、在线新版本需要另行部署验证。

## 交付

1. 中英文 README 首屏：一句定位、三条卖点、体验链接、真实截图、最短启动路径和环境版本；语言互链；保留已有中文运维锚点。
2. `docs/media/workspace-overview.png`、`access-preview.png`、`mobile-notifications.png`：真实界面，虚构演示数据。
3. `docs/media/demo-walkthrough.webm`：约 45 秒的实际操作演示，查看仪表盘、成员审批审计、通知和手机布局。
4. `docs/media/social-preview.png`：1280×640 分享封面，使用代码布局与真实截图；网站静态资源同步到 `public/social-preview.png`。
5. Webpack/Vite HTML 的 description、Open Graph 和分享图片信息一致；不修改真实身份或权限规则。
6. `docs/promotion/` 中保存渠道文案草稿、录屏分镜、七天执行清单和来源/体验/反馈记录模板。

## 授权边界

本阶段在仓库准备内容、代码和媒体文件；对外发帖、修改 GitHub 远端设置和正式部署不在本阶段自动执行。用户确认业务仪表盘仍保留演示数据。后续业务案例继续使用明确标记的演示数据。

## 验证

校验中英文事实、命令、链接与图片文件存在；统一 Node/pnpm 版本；检查截图与封面清晰度、视频时长和播放；运行文档/格式及受影响的构建工具验证；独立检查文案承诺、体验入口和交付素材是否一致。
