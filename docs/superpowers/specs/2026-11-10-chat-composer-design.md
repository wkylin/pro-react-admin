# 聊天室交互与输入区

## 已确认范围

用户要求参考 Studio Admin Chat 的整体交互，重点采用 Reply / Internal note 与格式、表情、附件、链接、写作工具组成的输入区。用户明确选择：

- 内部备注仅本人可见，保留在当前会话。
- 复用现有后端，附件使用已上传文件链接，写作工具生成提示词，不新增上传与文本模型服务。

## 设计与功能

统一输入卡片采用顶部分区标签、中间无重复边框编辑器、底部五个工具和独立图标发送按钮。表情、Markdown 格式与链接在当前选区插入，保留光标；Enter 发送、Shift+Enter 换行与 IME 保护保留。字符数按实际发送正文计算，含回复引用。

普通回复继续通过既有 groupchat 文本协议发送；当前客户端安全显示 Markdown，旧客户端仍可阅读原始文本。内部备注使用独立内存数据和草稿，不进入发送函数、REST、公共消息缓存或浏览器存储，断开/切账号清除。切换模式和房间保留各自草稿。

消息提供复制和引用回复；备注可复制、删除。会话列表支持本次连接的未读过滤、房间固定与清除本地新消息数。房间信息及参与者继续来自真实接口与已加载消息，不制造在线、已读或送达状态。

附件工具只插入真实 URL，不选择或假装上传本地文件。图片消息不自动请求远程图片。写作助手本地生成润色、精简、正式或翻译提示词，提供复制及工作台入口，不自动发送正文给外部 AI。

## 约束与验证

保留原 REST/XMPP 鉴权、加入确认、重连、失败草稿与时间线。消息仍最多 4000 个 JS 字符；私密内容不能因模式/房间/身份切换误发。所有测试使用受控 REST/XMPP，不向公共聊天室发送消息。

参考页已实际检查：其五个工具按钮为占位，只有模式切换和详情等部分交互真实存在；本项目补齐所选范围的可工作操作。桌面详情右栏、手机覆盖详情与返回列表保持可用。
