# 独立聊天室与 Chat Platform 集成

## 意图与范围

用户要求参考 Studio Admin Chat 改进前端，并使用项目已集成的聊天室后端。将现有隐藏在加密实验室中的接入能力扩展成独立 `/#/chat` 聊天室，保留原加密实验室与上一轮 Tavily 改动。

## 方案与决定

- 仅美化原加密实验室表单：保留工具属性，不能提供完整聊天室体验。
- 新增独立群聊工作区并复用既有 Chat Platform REST + XMPP：采用，协议与普通平台客户端兼容；无需新增或修改外部后端。
- 新建私聊或消息后端：不采用，现有服务只提供群聊，用户明确要求复用。

## 参考与界面

已只读查看 [Studio Admin Chat](https://studio-admin.arhamkhnz.com/dashboard/chat) 及其独立 `/chat` 工作台。借鉴可搜索会话列表、固定消息头与输入框、消息区独立滚动、按需展开详情栏、手机列表与会话单页切换；不重复套入参考站分类导航。

当前项目使用房间列表代替私聊联系人。桌面采用约 280px 房间栏、弹性消息区与可展开约 280px 详情；手机默认列表，选房间后进入消息页并可返回。沿用主题语义色、Geist、12px 容器圆角及 24/16px 间距。选房间与消息到达采用短暂位置/透明度变化，减少动态效果时静止；不以动画延迟发送。

## 真实后端契约

- 复用现有 Chat Platform API 地址与 `POST /auth/login`、`GET /rooms`、`POST /rooms/:id/join`、`GET /rooms/:id/messages?limit=80`、`POST /im/session`、`DELETE /im/session`。
- 历史仅支持最近记录，上限 200，没有游标；界面可刷新最近历史与扩大读取范围，不声称完整历史分页。
- 实时使用临时凭据连接 XMPP、发送 MUC presence，收到自身加入确认后加载历史；消息通过 `groupchat` 发送纯文本，4000 JS 字符上限。兼容既有普通客户端，原 AES 群聊工具不变。
- 服务器 echo 的 id/userId/displayName/createdAt 是消息依据；按服务端 id 合并实时与历史。发送到 socket 不等于送达或已读，不生成虚假回执。断线后重入并补拉历史。
- 后端没有私聊、typing、附件、完整在线名单或未读/已读接口。只展示真实累计加入人数、会话内观察到的新消息、历史参与者和本机连接状态。
- removed 消息的 body 在模型层清空；严格 AES 封包显示加密消息占位，不作为普通文本或解密内容展示。

## 交互与生命周期

1. 用户主动打开连接设置，使用现有账号或公开体验账号连接；不自动登录外部服务。接口地址可配置，WebSocket 地址来自短期会话接口。
2. 房间搜索、按房间保留的内存草稿、消息内容搜索、日期分隔、定位最新消息、历史加载/重试、房间详情与复制房间地址。
3. 切换房间需先完成加入；迟到的历史不能覆盖新选择。背景房间收到实际观察到的消息时累加本次连接内的新消息数，打开房间清零，不伪装服务端未读。
4. Enter 发送、Shift+Enter 换行；输入法组合期间不触发发送；空白/超长/离线消息不可发送。发送失败保留原草稿，提交成功后若用户已继续编辑不得清掉新草稿。
5. 上下文连接、令牌、临时口令、消息及草稿仅存内存；断开、切换项目账号/租户、页面卸载会取消请求、停止重连并撤销临时会话。无真实消息发送测试。
6. API 与 XMPP 分别提供固定错误码、超时、可重试状态，避免将响应文本或凭据注入界面。

## 路由与权限

新增默认应用 `/chat` 页面，侧边栏作为常用业务入口。沿用现有 `crypto:read` 权限，因为新页面使用与原实验室同一聊天服务能力，不扩大原本无权访问者的权限。Enterprise 精简入口不自动增加未注册页面。

## 验证

纯模型和 API 测试覆盖 removed、加密占位、参数边界与取消；实时 hook 注入 fake XMPP library 验证加入 ACK、echo、断线与并发；浏览器通过受控 REST 与 XMPP 协议替身验证连接、历史/实时合并、发送、输入法、切房、草稿、断线、账号隔离和手机主题。禁止向真实公共房间发送测试消息。
