# Studio Admin 对标与首轮设计

## 目标与依据

用户要求分析 [Studio Admin Default](https://studio-admin.arhamkhnz.com/dashboard/default) 的优势，并在当前项目逐步补齐。2026-11-09 实际查看参考页桌面布局、状态筛选、导航和客户表；同时检查当前路由、主题、权限、搜索及页面范式实现。

## 改造前差异与值得借鉴的优势

| 维度       | 参考站观察                                         | 当前项目                                          | 优先级   |
| ---------- | -------------------------------------------------- | ------------------------------------------------- | -------- |
| 业务首屏   | 指标、变化趋势和解释在同一张卡片里                 | `/dashboard` 是四张工程能力介绍卡                 | 本轮     |
| 数据到行动 | 活动图、时间范围、客户筛选与导出连续排列           | 图表、业务表单和管理页面已有，但入口分散          | 本轮     |
| 导航连续性 | 仪表盘和业务页共用侧栏与顶栏                       | dashboard 使用独立布局，返回按钮悬浮在内容上方    | 本轮     |
| 页面节奏   | 克制的边框、留白、数字层级与统一工具条             | 主题 token 已完善，演示页面的密度与标题仍不一致   | 下一轮   |
| 业务模板   | 导航列出 CRM、财务、分析、电商等多种场景           | 工程、可视化演示较多，常用业务模板数量较少        | 后续分轮 |
| 交互完成度 | 客户表提供搜索、状态、账单、日期、排序、选中、分页 | pagePatterns 已有完整表单流程；通知编辑仅打印日志 | 下一轮   |

参考页有标为 soon 且禁用的入口，不能将这些当作已经实现的模块。这里只确认实际查看到的界面行为，不推断参考站的真实后端、权限安全或性能。

当前项目已有权限搜索（含拼音、最近访问和键盘）、多标签缓存、明暗及系统主题、颜色/布局/密度设置、企业权限审批审计、表格到表单到详情的完整流程。优势在工程和权限基础，不需要为了外观切换技术栈或重建这些能力。

## 方案比较与本轮选择

1. 只统一视觉：变更小，但无法补齐业务概览。
2. 在现有主布局补齐业务概览：复用主题、权限与导航，直接形成可操作首屏。本轮采用此方案，由实现者根据用户“小步补齐”的要求选择。
3. 一次扩展 CRM 等全部模块：范围过大，不符合逐步推进。

## 本轮设计

- 保留工程首页 `/`。把已有 `/dashboard` 迁入主布局并加入可搜索的菜单；沿用 `dashboard:read`。
- 四张指标卡包含值、与上期变化和业务解释。用确定性的本地演示数据，明确展示数据日期和演示标识，不暗示真实接口。
- 活动趋势支持最近 7、30、90 天；指标和图表使用同一时间范围。图表有文本摘要和可访问名称。
- 客户表支持姓名/邮箱搜索、状态、账单、加入时间筛选、排序、分页、勾选和 CSV 导出。导出全部筛选结果或当前筛选范围内选中记录，避免隐含跨筛选选中。
- 搜索、筛选、排序、页码和时间范围放入 URL，刷新及浏览器前进后退可恢复。筛选改变后回到第一页。
- 客户详情抽屉展示对应记录；空结果有清除筛选操作。
- 沿用 Geist 和语义 CSS token。桌面四列指标，移动端一列，图表和工具条可换行，宽表只在自身滚动。
- 中英文一致，保留可见键盘焦点，支持深色和减少动画偏好。不增加依赖。

## 边界与后续顺序

本轮不修改企业数据 API，不新增持久化业务客户，不复制参考站整套品牌。不把参考站的菜单数量作为工程质量指标。

下一轮先统一常用业务页的标题、工具条、密度和导航分组；再补通知编辑及持久化契约；之后逐个增加 CRM、任务看板、日历等模板，每轮独立验证。

## 验收

`/dashboard` 在主壳中可达且遵守已有权限；搜索、组合筛选、排序、分页、详情和导出实际工作；URL 可恢复状态；390px 无页面横向溢出；中英文/明暗主题可用；通过相关单测、类型检查、路由及国际化契约检查。

## 本轮完成与验证记录

- 已将 `/dashboard` 接入主工作台、菜单和全局搜索，移除独立布局及旧工程介绍内容。
- 已实现四张趋势指标卡、7/30/90 天活动图、60 条确定性客户记录、组合筛选、排序、分页、详情和 CSV 导出。选择跨页保留，筛选范围变化时清空；恢复旧筛选不会恢复旧勾选。
- 所有数据固定截至 2026-11-09。收入按已付款方案每天确认 USD 1/3/9（入门/专业/企业），历史活动是当前状态回推的演示重建，不是真实生命周期或账单。增长率表示周期内活跃账户增幅，卡片变化值均相对上一等长周期计算。
- 修复了通用路由授权把查询参数当作 pathname 的问题：普通用户从已保存标签返回筛选结果时，现在保持地址参数并按原页面权限检查。
- 相关 Jest 共 6 组、43 项通过；类型检查、修改文件 ESLint/Stylelint/Prettier、路由、国际化、导入边界和文档契约检查通过。
- 浏览器实测了中英文、桌面和 390px、明暗主题、搜索/组合筛选、空结果、日期筛选、排序、分页、选择导出、详情、刷新、浏览器后退和普通用户标签往返。390px 页面 scrollWidth 为 390px。
- 新增区域 axe 检查为 0 个违规；SVG/被覆盖元素的颜色对比有 1 项需人工判断的未完成检查。已使用现有主题语义色并目视检查明暗主题。

第一轮后的差距已在[工作台第二轮优化](2026-11-09-workspace-polish-design.md)中继续处理：导航分组、共享页面结构、通知编辑闭环已完成。CRM 和客户收入接口仍作为独立业务迭代；用户已选择先保留演示仪表盘、完善使用体验。第一轮没有执行生产构建或部署。
